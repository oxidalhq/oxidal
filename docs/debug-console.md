# Web debug console

## Implemented restricted console

Settings includes an explicitly enabled, five-minute debug mode. The same authenticated HTTPS and origin restrictions apply as other appliance API calls. It sends commands to a separate `oxidal-debug` service account; the web daemon and root network helper never execute command text.

- The UI shows execution identity and working directory. Each command starts a fresh non-interactive `/bin/sh` with a clean environment, null stdin and no persistent shell history. Do not put credentials in commands: their output is intentionally visible to the authenticated owner.
- One command runs at a time, with a 2 KiB command limit, 8 KiB combined stdout/stderr limit and 30-second deadline. Output streams through bounded buffers and status polling. HTTP status reads return the latest confirmed snapshot without waiting for executor IPC; background polling updates it, including during service recycling. Cancel targets an exact job identifier; accepted commands are never replayed automatically.
- Closing the browser leaves the accepted command running until completion/deadline. The daemon retains the latest result in memory for reconnect. Disabling debug mode cancels a running job. Mode and output do not persist across daemon restart.
- The runner kills the shell process group and reaps its direct child. After delivery of the terminal result, or a two-second terminal-result timeout, the executor exits; systemd cleans its entire control group before restarting it. This also contains descendants which create a new session. The final result remains in daemon memory.
- The service refuses root, requires its dedicated account and checks Unix peer identity. Its unit has no capabilities, no privilege escalation, read-only system/home protection, private temporary/device namespaces, a 32-task ceiling, 128 MiB memory limit and 20% CPU quota. Scratch working files disappear when the service recycles. Commands cannot alter network settings or install packages; those still require authorized administration.

The existing Rust suite tests output/exit status, output floods, timeout and cancellation. HTTP tests cover disabled/unavailable behavior, strict request parsing and foreign-origin rejection. Playwright covers enable/run/reconnect/cancel and command-storage avoidance. The assembled-image boot suite additionally verifies real service identity and cancellation of a descendant outside the shell process group. A disposable non-systemd container cannot establish the last guarantee on its own.

## Interactive terminal

Settings → Maintenance → Interactive terminal opens a persistent Bash PTY under the separate `oxidal-debug` identity. Start terminal explicitly creates a shell; closing the panel or browser leaves it running. Reconnect attaches to the existing session without replaying commands. End session terminates it and systemd removes its complete process group and cgroup, including detached descendants. Shell exit also recycles the terminal service. Restarting the terminal service, daemon host, or appliance is not a persisted terminal session.

- Commands have no application runtime deadline or total-output cutoff. The earlier runner remains a separate, explicitly labelled restricted diagnostics option; its limits do not apply to this PTY.
- Input, interactive prompts, Ctrl-C, terminal resizing and working directory/environment persist within the session. The terminal starts without profile/startup scripts, with `HISTFILE=/dev/null` and no saved shell history. The initial working directory is `/run/oxidal-terminal`; temporary files disappear when the service recycles. A user command can still explicitly write files to permitted locations.
- The server retains a 256 KiB output replay window; the browser retains 2,000 scrollback lines. Output continues indefinitely. If a slow/disconnected browser falls behind, the view explicitly marks missing older output. Reconnection replays retained bytes, not a complete screen snapshot for arbitrary full-screen applications; redraw such applications if necessary.
- Input packets have session/sequence checks and a bounded pending queue. Ambiguous failed requests are never retried; reconnect reads the confirmed input sequence before accepting new typing. Multiple connected viewers share one shell; concurrent writers may receive an input-sequence conflict instead of silently duplicating input. No input/output is stored by the web app in browser storage or server logs.
- The authenticated appliance proxy and origin checks protect the endpoint. Fixed Unix-socket identity checks reject impersonation. The web daemon never spawns the shell and the privileged network helper never receives command text.
- This is the **unprivileged** mode: `NoNewPrivileges`, read-only system/home protection and no capabilities remain in force. Commands requiring `sudo`, package installation or system modification remain unavailable here. There is no automatic five-minute expiry, per-command output cutoff or 30-second deadline, and the previous runner's custom CPU/memory quotas do not apply. Normal OS limits and available resources still apply.

The Administrator option opens a separate persistent shell as `oxidal-admin` in `/home/oxidal-admin`, explicitly authorized for this development image. It starts only after Start terminal. `sudo` uses the existing recovery administrator password, with normal OS sudo policy; the web service does not store or bypass that password. Unlike the unprivileged mode, this service permits system changes through sudo. It retains the authenticated HTTPS/origin boundary, fixed socket/account mapping, input sequence checks and complete cgroup cleanup. Switching modes leaves the other shell running; explicitly end each session when finished. The root network helper remains separate. This development maintenance access must be reviewed before a public release.

Repeatable coverage lives in the existing suites: real-PTY Rust tests (input, environment, resize, replay window, sequence conflicts, Ctrl-C, over-8-KiB output and a 31-second command), API origin/availability tests, browser reconnect/lost-reply/rotation cases on target devices, and the assembled-image QEMU test for real service identity, `NoNewPrivileges`, retained state and escaped-descendant cleanup. Physical device/keyboard usability and running heavy debug tools alongside real audio still require hardware acceptance.
